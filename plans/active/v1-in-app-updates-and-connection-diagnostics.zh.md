# v1 源码预发布：连接诊断、应用内增量更新与快速启动

## 最新范围决定（覆盖下方原发布安排）

用户在本轮实施中明确改为：**暂不构建 exe / mac 应用，优先源码快速迭代**。当前版本改为 `1.0.1a1`（预发布），不生成 Tag、不发布 Release、不触发构建 CI。已有 v1.0.0 Release 及接受清单保留，不假装含有新改动。

本轮收尾：保存已实现的连接诊断和更新链路代码，提供 `scripts/run_desktop.py --setup` 一次准备及日常源码启动入口；仅做相关定向验证。安装包更新仍待后续平台产物验收，不能宣称现有用户已经可以通过设置安装本轮修改。

## 目标与当前事实

- 起点 `main/d8b5c06`；已有 v1.0.0 只能下载完整 ZIP/DMG 并打开目录，没有安装器。
- 用户接受这次重新安装过渡版本；之后从设置完成下载、校验、安装和重启，不要求重新下载完整安装包。
- 连接错误的 401、初始化异常可能退化成“操作未完成”；现有 mac smoke 使用 null keyring，不能证明真实 Keychain / AI 连通。
- 本轮不读取真实 Profile、Key 或材料，不修改面试协议、课程、评分和语音。

## 决策

1. 原拟正式版本号 `1.0.1`，现按最新决定改为源码预发布 `1.0.1a1`。将来恢复打包发布时，v1.0.0 用户需最后一次安装新包，这是旧客户端能力限制。
2. 更新协议 v1 使用完整文件清单、SHA-256、压缩数据块与小文件包。客户端复用相同文件及大文件的相同块，不下载完整 ZIP/DMG。无需相邻版本补丁链，旧版本可直接匹配新清单。
3. 下载来源限制为本仓库 GitHub Releases / 官方 CDN；不关闭 HTTPS 校验。清单与 payload 均验证散列，路径限制于新建 staging，禁止覆盖运行中程序。
4. 平台脚本在旧进程退出后换入已验证的新目录；保留回退目录，启动失败回退。新程序完成 QML 启动后确认成功。保留现有关闭/未保存内容门控。
5. 发布必须生成 Windows/macOS 更新清单和 payload，并执行重建比对；缺少更新协议资源不允许正式发布。不能保证任意未来 OS/架构变化均无条件兼容；不兼容时明确停止，禁止隐式回退成全量重装。
6. 诊断仅记录阶段、固定错误码、HTTP 状态、异常类型、应用版本、平台和请求编号。不得包含 Key、Authorization、材料、请求/响应正文、个人路径或完整自定义 URL。界面可复制脱敏诊断。

## 实施切片与验收

1. 连接诊断：保存/读取密钥、参数校验、客户端初始化、网络与服务拒绝分开；针对性模拟 401/403/429/证书/DNS/超时/Keychain，核验无 secret 泄露和重复翻译。
2. 增量发布及 staging：变化/新增/删除/移动、符号链接、文件权限、错误散列、中断、跨版本；用已下载公开 v1 bundle 验证数据结构，不访问真实数据。
3. 应用内安装：真实 Qt 设置按钮/关闭门控；Windows、macOS 原生脚本在 CI 验证退出、替换、启动确认、回退。正式包验证版本、更新资源与连接依赖；不以 mock 代替 mac 实机结果。
4. 更新中英文 README、使用指南及预发布说明。提交 main 并使用 `[skip ci]`；本轮不构建与发布。

## 风险与停止条件

- 本机是 Windows，mac 安装/Keychain 只能由 mac runner 验证，室友机器仍需人工复测。
- 只读安装目录、磁盘空间不足、签名/校验不符或更新资源不可达时保持旧版；不强制关闭应用、不删除用户数据、不降级 TLS。
- 编译主程序大幅变化会产生较多块，增量更新不等于固定小体积。
- 不删除既有未跟踪文件或历史 Release，后续清理不得移除仍被更新清单引用的资源。

- 源码入口只使用已有标准库。`--setup` 才安装依赖，普通运行不下载、不打包、不清理数据；默认数据目录与原先手动 UAT 命令一致，显式覆盖仍有效。

- 成功更新目前保留历次备份目录；回退目录保留策略、mac 安装权限与公证、真实包重启握手仍需平台验收，不能用本机合成脚本结果代替。
- 既有未跟踪文件、人工 UAT 数据和原始资料全部保留；只提交任务明确产生的源码、测试与文档。
