# INT-025 · 把用户反馈变成可审计的评测与数据飞轮

## 情境（完全虚构）

一个企业知识助手上线两个月后，点赞率上升，但客服仍不断报告“助手自信地给出过期政策”。
产品每两周发布一次；政策每周更新，而且不同地区的规则并不相同。你只有每周两百条人工审查预算。

已知事实如下：

- 只有约一成会话留下显式点赞或点踩，高活跃用户更愿意反馈；
- 当前离线评测集主要来自上线前的合成数据；
- 团队不能默认把会话内容用于训练；
- 新版本需要同时比较模型版本和检索版本。

## 主问题

请设计一条从反馈采集到发布决策的数据飞轮。你的方案至少要说明：

1. 如何区分显式反馈、行为信号、客服升级和随机抽样审查，并识别选择偏差；
2. 如何取得用途绑定的授权、最小化敏感内容，并支持撤回和删除；
3. 如何建立可版本化的错误分类（taxonomy），覆盖过期政策、地区错配、检索缺失和模型臆测；
4. 如何在两百条预算内组合随机样本、风险样本和新鲜政策样本；
5. 如何隔离训练、开发和受保护的发布回归集，避免反馈泄漏；
6. 如何选择检索、Prompt、产品流程或模型训练等干预，并定义发布、暂停和回滚门槛。

请明确哪些是题目给出的事实，哪些是你的假设；不要凭空补充用户量、准确率、业务收益或地区风险比例。

## 约束

- 会话内容不是默认可训练数据；每一种用途都要有单独授权和访问边界。
- 点赞不是无偏质量标签；不能用总体点赞率掩盖严重或小群体风险。
- 每个重要指标都要说明分群、时间版本、样本来源和不确定性。
- 方案必须能在两周发布节奏内留下可审计的决策记录。

## 面试官可能追加的信息

面试官可以逐步透露：同一政策的改写样本被用于 Prompt 调优、某地区投诉集中、人工标注分歧很大、或新旧版本的流量分配并不均衡。收到新证据后，请更新判断，不要为原方案辩护到底。

## 证据要求

- 画出“反馈 → 分类/抽样 → 受保护评测 → 干预 → 发布门槛”的闭环；
- 指出一个会误导团队的聚合指标，并给出校正方式；
- 给出至少一个无法下结论的情况，以及需要补采的证据；
- 说明谁能批准使用数据、谁负责发布或回滚。
