# INT-027 · 训练吞吐下降的跨层瓶颈定位

## 情境（完全虚构）

同一个模型从 8 卡扩到 64 卡后，监控显示平均 GPU 利用率仍约为 92%，但每个 token 的训练时间比预期慢了约四成。
每 50 个 step 会出现一次长尾；数据加载器 CPU 利用率和对象存储吞吐看起来正常，collective 的平均带宽也正常，
但不同 rank 的带宽差异明显。最近一次发布同时升级了数据格式和通信库。你只有两小时诊断窗口，不能改变主训练数据。

## 主问题

请设计一条“先测量、再归因、最后验证优化”的路径。请覆盖：

1. 一次 step 如何按 compute、collective、输入/解码、同步等待和存储检查点拆分，并在 rank 间建立可对齐的时间线；
2. 为什么平均 GPU 利用率不能单独代表 useful work，如何定义 throughput 与 goodput；
3. 根据周期性长尾、rank 差异和双变量升级，优先提出三个可证伪假设；
4. 如何用不影响主训练的单变量实验隔离数据格式、通信库、straggler 或检查点因素；
5. 若发现单个 rank 的输入变慢，如何修复而不悄悄改变批次、顺序或训练语义；
6. 如何用性能、正确性、稳定性和成本的共同门槛决定是否保留优化。

请明确哪些数字只是题设事实，哪些指标还需要采集；不要把“增加 batch”或“换更大 GPU”当成诊断结论。

## 约束

- 诊断只读主训练证据；实验应使用隔离的影子流量、回放或合成输入。
- 不能同时修改通信、数据和编译配置后再声称找到了根因。
- 不能用平均值掩盖单 rank 长尾，也不能用更快的 step 掩盖 loss 或样本语义改变。
- 每个优化动作都要有回滚方式和观测窗口。

## 面试官可能追加的信息

面试官可以透露：长尾与对象存储请求周期重合、某两个 rank 的输入队列更短、通信库只在特定拓扑上退化，
或检查点恰好每 50 step 触发。请据此更新假设优先级，并指出仍不能确定的部分。

## 证据要求

- 画出至少四段的 step 时间线，并标注 per-rank 证据；
- 为前三个假设各给出一个可证伪观测和一个最小实验；
- 定义同时保护训练正确性与端到端 goodput 的成功门槛；
- 说明实验负责人、回滚触发条件和最终记录。
