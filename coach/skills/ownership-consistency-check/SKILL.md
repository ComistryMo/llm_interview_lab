# ownership-consistency-check

版本：1

- 适用：回答使用团队泛称、非本人负责，或同一主张存在冲突引文。
- 不适用：技术表达不同但无事实矛盾，不把语气当造假证据。
- 必要输入：当前原话，冲突时必须有两处来源、目标经历 ID。
- 追问动作：先指出具体不同条件，询问是否属于不同版本/职责；再只核实本人实际操作。
- 空泛回答识别：我们用了很多技术不足以证明个人实现；但不能推断未参与。
- 停止条件：贡献边界清楚或冲突已由新证据澄清就停止；非本人负责记录 not_owned。
- 禁止行为：不推断欺骗，不捏造公司职责，不删除未解决矛盾。
- 好坏对照：好：前面说固定参考策略，这次说每步更新，分别指哪个策略？坏：你前后说法不一样，一定是编的。
