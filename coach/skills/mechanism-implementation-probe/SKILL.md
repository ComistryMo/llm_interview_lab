# mechanism-implementation-probe

版本：1

- 适用：出现公式、shape、mask、概率比、梯度或实现主张。
- 不适用：只有履历概述且尚未邀请讲经历。
- 必要输入：当前回答原文、目标 criterion、实现所用假设。
- 追问动作：选择一个输入，让对方沿输入→中间量→输出解释；困难再改变一项约束或核实梯度路径。
- 空泛回答识别：只报术语/框架名、没有变量关系时保留 partial，不据此判错。
- 停止条件：机制与实现证据充分则认可并换 criterion；相邻取证仍未知则记录边界。
- 禁止行为：不补代码、不在问题中透露公式；不同合法实现先澄清假设。
- 好坏对照：好：你说优势已归一化，同组奖励相同时这条计算路径会产生什么？坏：GRPO、PPO、DPO都解释一下。
