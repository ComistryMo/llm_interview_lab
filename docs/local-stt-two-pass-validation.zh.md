# 流式预览 + Qwen3-ASR 0.6B 停句校准：本地验证

日期：2026-09-08；源码基线：`main / cb3d13b`。

> 后续状态（2026-09-09）：该组合已接入正式面试语音输入，见[正式应用接入与验证](local-stt.md#正式双阶段应用验证2026-09-09)。下文保留接入前实验记录，不将实验性能冒充正式页面性能。

## 裁决

**组合管线技术验证通过，准确率有明确限制；尚未接入正式应用，不替换默认模型。**

本次不是把两份单模型成绩放在一起推断可行，而是在同一进程同时运行预览和校准，按真实时间连续送音，实际观察它们并行工作。

已验证的组合是：

`本地 PCM → Zipformer 实时预览 + Silero 人声停顿检测 → 已停顿语音段交给本地 Qwen3-ASR 0.6B → 按段 ID 更新识别结果`

校准期间下一段继续产生预览。Qwen 接收的是该段原始音频，不是流式识别文字，也不接收样例参考答案、简历或热词。没有调用云端 ASR，没有 API 费用；没有开启麦克风、读取私人录音或访问 Profile。

## 先发现的问题及实验修正

第一版直接沿用流式识别端点，并跳过没有预览文字的片段。实测这不是可靠的人声切句：

- 正常停顿样例中，37.60–40.10 秒被当成“空文本片段”跳过；该范围包含 AdamW 所在录音的开头。后续 0.6B 没收到这段声音，无法恢复术语。
- 一些识别端点把相邻词的声音拆开；Qwen 在切碎的段上会省略或误写。
- 该版正常 / 短停顿样例校准后仍有 **19 / 16** 个字符错误。它不满足本轮预期，保留为失败对照，而不是发布实现。

第二版加入独立的本地 Silero VAD，根据人声停顿触发分段，不再以“预览是否有字”决定人声是否有资格被校准。使用已有 sherpa-onnx，无需安装新 Python 包。实验配置为阈值 0.5、最短人声 0.25 秒、静音 0.8 秒、连续语段上限 30 秒。[sherpa 官方 VAD 说明](https://k2-fsa.github.io/sherpa/onnx/vad/silero-vad.html)

音频块按连续样本范围交给校准器，验证其哈希与原始 PCM 对应范围一致；没有拼接参考答案、依靠关键词替换结果或重新识别整场录音。预览与校准按段 ID 替换，不把两种识别结果重复追加。

## 实际数据

Windows / i7-12850HX / 16 GB RAM / sherpa-onnx 1.13.7。Zipformer、0.6B 各使用 CPU 2 线程，VAD 1 线程，未使用 GPU。模型预先加载后，Qt 每 20 ms 检查事件，每 100 ms 送入一块 PCM；识别在两个后台工作通道执行。

复用[单模型对照](local-stt-comparison.zh.md)中的 7 条本机 TTS 技术术语语音和 4 条公开真人语音。连续实验使用的停顿由程序插入；**切句不读取音频清单中的句子边界**。

### 术语合成样例

两种停顿配置参考文本相同，均为 261 个归一化字符；音频内容分别与第一版失败对照的 PCM SHA 完全一致。

| 场景 | 音频长度（含停顿） | 实时预览 CER | 直接识别端点 + 0.6B（失败对照） | 人声停顿 + 0.6B |
|---|---:|---:|---:|---:|
| 每条之间插入 1.2 秒停顿 | 65.045 秒 | 37 / 261 = 14.18% | 19 / 261 = 7.28% | **6 / 261 = 2.30%** |
| 每条之间仅插入 0.25 秒停顿 | 58.395 秒 | 43 / 261 = 16.48% | 16 / 261 = 6.13% | **5 / 261 = 1.92%** |

CER 使用 NFKC、小写化，忽略标点和空白；英文按字符而非单词计数。这里的“实时预览 CER”属于第二版运行；第一版预览的分段不同，正常场景为 38 个错误。不可混用这些分母或把两轮停顿回放当成两组独立说话人。

第二版保住了 GRPO、DPO、PPO、MHA、GQA、KV Cache、AdamW、RMSNorm；否定句中的“没有证明”“没有采用”保留。仍有“验证集”同音误写，LoRA 仍被写成 Laura。正常场景还出现“变好 → 便好”。**没有做到无错转录。**

### 延迟与响应

| 场景 | 首次预览 | 检测到停顿后校准完成 | 停止送音后的最终收尾 |
|---|---:|---:|---:|
| 正常停顿 | 0.82 秒 | 1.08–2.70 秒 / 段 | 0.87 秒 |
| 短停顿 | 0.82 秒 | 1.10–2.59 秒 / 段 | 1.77 秒 |
| 4 条公开真人语音连续回放 | 1.14 秒 | 0.89–2.25 秒 / 段 | 0.04 秒 |
| 不追加停顿，直接结束 7.39 秒音频 | 0.84 秒 | 停录后处理尾段 | 2.13 秒 |

“检测到停顿后”不包含前面的约 0.8 秒静音判定；从用户停止说话算起通常还需加上这部分。公开真人场景末尾人为保留了停顿，校准多数已在录音结束前完成，**不能把 0.04 秒宣传成普遍停录延迟**。

- 正常 / 短停顿 / 公开真人场景在 Qwen 工作期间，仍分别产生 **13 / 19 / 2 次**新的预览更新。
- 本批最大待校准段数为 1，未观察到积压。没有据此保证所有长回答都不积压。
- 第二版各场景 Qt 心跳最大间隔不超过 **45 ms**，通过本实验 `<100 ms` 的门槛；没有出现秒级线程阻塞。这是 QCoreApplication 事件循环，不是正式窗口渲染的帧率测试。
- 双 ASR + VAD 的实验进程峰值工作集约 **2086 MiB（2.04 GiB）**。不代表整套桌面应用只需这些内存，也不代表最低配置。
- 第二版首次模型创建约 6.14 秒，发生在回放前。未验证正式 UI 冷加载；没有把预热后的延迟当作首次启动体验。

## 七项交互边界验证

1. 正常停顿连续回答：有预览、有逐段校准，音频范围对应，未重复追加。
2. 短停顿连续回答：后续预览未被校准阻塞，最终文本完整组装。
3. 公开真人混说：处理完成，无运行异常；没有独立参考文本，不计算准确率。
4. 纯静音：不提交 Qwen 校准任务，不产生文字。
5. 校准进行中取消：迟到的真实 Qwen 结果被忽略，未写入最终文本；原生推理仍自然结束，约 1.98 秒后排空后台任务，期间 Qt 心跳正常。
6. 取消后重新录音：复用加载后的模型，新录音成功产生自己的文本。**本项是在旧任务排空后重启，不是旧任务未结束就立即切换 Profile 的验证。**
7. 无额外停顿直接停止：flush 最后一段并完成校准，不丢掉尾段。

七项均通过：无推理异常、每段完成结果只处理一次、原始手打字符串与录音中补充字符串未变、校准音频与源 PCM 哈希一致；非取消场景的全部输入范围有记录。这些是**试验脚本中的状态断言，不是正式回答框/输入法/Controller 的验收**。音频范围完整记录也不等于模型没有漏识别。

## 必须保留的质量限制

公开真人中英混说出现明显分歧。例如预览中的“频繁”被第二遍写成“平凡”，`always` 被写成 `OS`。虽然本轮没有独立校对文本，不能统计真实准确率，但这些输出说明：**第二遍不天然保证更忠实，不能无条件相信所谓“校准”。**

本轮裁决是：技术方案可进入应用接入验证，**不应直接静默替换默认模式、自动提交回答或覆盖用户手动编辑**。正式接入仍需要：

- 保留可检查的识别草稿与原始录音；校准仅作用于其对应的语音片段，用户手改内容不能被迟到结果覆盖。
- 用用户明确授权、带人工参考文本的真实麦克风样本验证口音、术语、噪声、否定句与数字；当前合成成绩不能代替。
- 验证正式 QML 的取消、离页、立即重新录音、切题 / 切档隔离、冷加载、内存不足时的本地失败提示；不得偷偷回退到云端。
- 本次最长回放约 65 秒，但其中存在停顿。没有覆盖真正持续 30 秒以上不停顿的人声强制切段，不宣称长语段边界已经完善。

## 证据与复验

脚本：[verify_two_pass_local_asr.py](../scripts/verify_two_pass_local_asr.py)。不传 `--vad-model` 可复现第一版失败对照；传入后使用独立人声切句。只读取显式模型目录和测试音频清单。

所有模型、录音和详细事件位于 ignored 目录 `workspace/maintainer/local-asr-comparison-20260908/`：

- `results/two-pass.json`：第一版六场景，保留失败样例。
- `results/two-pass-vad.json`：修正切句后的六场景。
- `results/two-pass-stop.json`：额外的直接停录验证。
- `models/silero-pypi-5.1.2.onnx`：独立 VAD 模型。

VAD 来自 [Silero VAD 5.1.2 官方 PyPI 包](https://pypi.org/project/silero-vad/5.1.2/)，只提取其 `silero_vad/data/silero_vad.onnx`，没有安装或执行该包。包 SHA-256 与 PyPI 元数据匹配：`93b41953d7774b165407fda6b533c119c5803864e367d5034dc626c82cfdf661`。模型为 2,327,524 bytes，SHA-256 为 `2623a2953f6ff3d2c1e61740c6cdb7168133479b267dfef114a4a3cc5bdd788f`。下载仅用于取得公开权重，不是远程语音识别。

本机复验命令（模型已经准备好，不自动下载）：

```powershell
$env:PYTHONIOENCODING = 'utf-8'
$asrRoot = 'workspace/maintainer/local-asr-comparison-20260908'
.\.venv\Scripts\python.exe scripts/verify_two_pass_local_asr.py --preview-model workspace/maintainer/manual-uat/models/stt/zipformer-bilingual-streaming-int8 --qwen-model "$asrRoot/models/qwen/model_0.6B" --vad-model "$asrRoot/models/silero-pypi-5.1.2.onnx" --manifest "$asrRoot/evaluation.json" --output "$asrRoot/results/two-pass-recheck.json"
```

脚本中的 Python socket 连接被禁用；这不是操作系统级全进程网络审计。没有修改生产 QML、Controller、Provider、语音默认配置或用户数据；没有进行全量 pytest、CI、打包、发布或云端模型调用。
