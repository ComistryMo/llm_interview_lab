## 不打包也能测试

推荐 Python 3.11。首次运行 `python scripts/run_desktop.py --setup`，之后运行 `python scripts/run_desktop.py`。脚本使用仓库自己的 `.venv` 与 `src`，不需要激活环境、手动设置环境变量或等待编译。

修改 Python/QML 后关闭再启动即可；只在依赖变化时重新执行 `--setup`。数据默认留在 `workspace/maintainer/manual-uat`，不会重置；也可以用 `--data-root` 指定另一目录。详细的 Windows/macOS 命令见[源码启动指南](desktop-app.md#源码运行)。

## 连接出错时可以定位了

- AI 连接页区分 Key 保存/读取、网络客户端初始化、DNS、证书、代理、超时、鉴权和服务端错误。
- 401 不再显示成“操作未完成”；错误旁提供“复制脱敏诊断”。
- 诊断只含固定错误码、阶段、HTTP 状态、异常类型、应用版本、平台及请求编号。不复制 API Key、个人路径、材料或请求/响应正文。
- 保存 Key 后验证能够读回，不能保存的密钥环不会再显示为保存成功。

这改善诊断，不等于已经确认或修复每一台 Mac 的连接故障。真实账号、网络、代理及钥匙串权限仍需根据具体错误处理。

## 应用内更新实现（待打包验收）

以下为已加入源码、尚未在新 Windows/macOS bundle 上验收的流程；**目前不要求用户下载新安装包，也不能从旧 v1.0.0 设置里安装这些未发布改动**。以后恢复打包时，旧版用户才需要一次性安装带新更新器的过渡包。

1. 打开「设置 → 应用更新」，点击「检查更新」。
2. 点击「下载增量更新」，程序复用本机未变化的内容，只拉取变化块/小文件组并校验。
3. 点击「安装并重启」，确认后先保存草稿、关闭旧程序，再切换到新版。

更新不要求下载完整 ZIP/DMG，也不需要重新配置 Profile、API Key 或语音权重。程序大幅变化时下载仍可能较大，实际下载及复用量会显示。源码运行不会覆盖 Git 工作区。

新版本发布必须带两平台更新清单、SHA-256 与增量对象；缺少资源不能正式发布。协议支持直接跨版本更新，不要求逐版安装。每版独立携带需要的对象，不依赖保留中间版补丁链。

## 失败与限制

- 下载或校验失败不替换当前程序；支持原位重试。只读目录、磁盘空间不足或文件占用会明确报错。
- 安装在退出后执行，保留上一个程序目录。新版启动退出时回退；超时未确认但进程仍存活时不强杀进程，保留两份程序并显示未确认状态。
- mac 应用须先从 DMG 拖入本地应用目录；macOS 系统版本不支持新版时停止更新，不用重装掩盖不兼容。
- macOS 仍为 ad-hoc 签名，未完成 Developer ID 公证；首次安装可能需要系统允许打开。原有 PyTorch、DeepSeek 高推理及语音准确率限制没有因本次更新消失。
- 新发布路径要求提供应用内增量资源，不把全量包下载冒充增量更新。未知未来 OS/架构变化仍可能不兼容，不能以源码测试代替平台验收。
- 成功安装会保留回退目录，目前不自动清理历次成功安装的备份，后续需验证保留策略。
