# 候选版同机性能验证

2026-09-09；Windows x64、Python 3.11.9、PySide6 6.11.2，正式 Controller/QML，1440×900、软件渲染。每组 5 个新进程及新 synthetic 档案，无真实材料、凭证、网络或语音输入。没有清除系统文件缓存，因此称为进程冷启动，不称为裸机冷启动。

基线 `b319934`；最终源码 `9bebba5f3b4c69fa24a8aa1c8606972b6b57e5b2`，测量时 tracked diff 为空。后者与 Windows `f0b173c` 包的生产源码相同，但下表是源码运行数据，不冒充便携包耗时。最终测量期间本轮编译、测试和原生验收应用均已结束。

| 场景 | 修改前中位数 | 最终中位数 | 最终 p95 | 预先冻结的验收 |
|---|---:|---:|---:|---|
| 启动到点击侧栏成功 | 4434 ms | 4733 ms | 5500 ms | 增幅 ≤20%；实际 +6.75% |
| 知识页首次打开 | 33.74 ms | 39.77 ms | 49.83 ms | 增加 ≤50 ms |
| 连续搜索（120 次） | 42.19 ms | 24.98 ms | 35.63 ms | 降低 ≥25%；实际 -40.81% |

| 最终进程工作集 | 289.95 MiB | 294.57 MiB | 294.71 MiB | 增幅 ≤15%；实际 +1.60% |

p95 采用包含端点的线性分位数；只有 5 个进程样本的项目，p95 不代表大样本稳定尾延迟。最终五次启动原始值约为 5690、4727、4733、4532、4740 ms，第一次仍明显较慢。

改动只消除每次知识查询对已验证公共知识卡的重复文本展开。120 次查询的命中 ID 和排序逐项一致；文件变化继续触发快照失效与重新验证。不缓存 Profile、面试上下文或材料授权，也未降低题目验证标准。

原始数据：[基线及初次优化](desktop-candidate-20260909.samples.json)、[最终五次样本](desktop-candidate-20260909.final.json)。保留初次测量而不以较好样本覆盖最终结果。

复现：在安静的同机环境运行 `python scripts/benchmark_desktop_candidate.py --samples 5 --output <新的结果路径>`。脚本新建隔离公共资源及合成档案，每次启动一个真实 Qt 进程；资源准备和 40 轮记录构造不计入界面计时。用户机器、显卡后端、模型加载和网络等待会产生不同结果，不承诺固定秒级响应。
